# Этап 9. Пакет руководству: .xlsx и письмо

Руководитель, читая пакет, должен видеть, что сроки реализуемы, если всё движется так, и понимать риски: за каждым —
ответственный и срок. Пакет собирает скрипт из карты, а не ты из памяти. Формат листов — `format.md`, раздел «Пакет
руководству `.xlsx`».

## Делаешь

1. Проверяешь карту: `bin/roadmap lint <папка цели>` — «Принято», `bin/check-qlinks <папка цели>` — 0.
2. Сверяешь даты: `estimate: подтверждена` стоит только там, где срок оценила команда (со слов команды или PO) или
   работа выполнена. Ставить `подтверждена`, «чтобы появились даты», нельзя.
3. Собираешь:
   ```bash
   bin/roadmap xlsx   .okr/roadmap/<цель> -o reports/<Цель>_Roadmap_<ДД.ММ.ГГГГ>.xlsx --track N --date ГГГГ-ММ-ДД
   bin/roadmap letter .okr/roadmap/<цель> -o reports/Письмо_руководству_<ДД.ММ.ГГГГ>.txt --track N --date ГГГГ-ММ-ДД --xlsx <имя .xlsx>
   ```
   `--goals 1,2` — какие цели на листе «Roadmap» (по умолчанию цели с эпиками). Файл руками не правишь: нужна другая
   подача — правишь md и собираешь заново.
4. Фактчек перед отправкой (рекомендация: в исходном проекте делался роем) — `templates/workflows/factcheck-workflow.js`:
   три линзы — «карта» (каждое число и дата против md и csv), «источники» (обобщения против `sources/`), «читатель»
   (что вводит руководителя в заблуждение).
5. Отдаёшь PO пути к файлам и одну строку: целей, эпиков, историй, задач, открытых вопросов (печатает команда).

## Правила пакета (утверждены PO)

- Четыре листа: «Roadmap» (цели по неделям, ★ окончание цели, ◆ окончание эпиков), «ГАНТТ» (Цель → Эпик → История →
  Задача: ЦС → шаг → подзадача → пункт DoD), «Реестр вопросов» (открытые: ожидаемый ответ, ответственный, срок,
  «Влияет на»), «Беклог задач» (ключевые требования, демо, сроки, открытые вопросы).
- **Даты на «ГАНТТ» и в беклоге — только оценка команды или выполненная работа.** Остальное без дат до оценки.
- **Без кодов WBS, номеров задач плана и ссылок на созвоны в названиях и требованиях**; номера вопросов `Q-NN` остаются.
- Без сносок, легенд и пустых «ключевых точек», которые PO не просил.
- Письмо — простым языком: что сделано, как читать вложение, что важно знать. **Блока «Что нужно от вас» нет, если
  PO его не просил.** Числа — из команды `letter`, не набранные руками.
- Предложенное агентом (ответственный, срок) — с пометкой «предложение, не подтверждено».

## Промпты PO

```
Сделай xlsx для руководства по <треку / цели> и письмо к нему. Даты — только где есть оценка команды или работа сделана.
```

```
Подготовь пакет для <гендиректор, CPO, CTO>. Будь предельно внимателен, не выдумывай. Перед отправкой — фактчек.
```

## Ошибки, которые PO поправлял

- Письмо «ИИ-слоп нечитаемый» → простой язык, нормальный тон для руководства.
- Длинный реестр руководителю («полная дичь, непонятная») → 3–5 измеримых решений (`roadmap-03-questions`,
  `resources/questions-registry.md`, «Реестр для руководства») или лист «Реестр вопросов».
- Счётчики в письме набраны руками и разошлись с картой («21 вопрос» при 22) → числа только из команды и сверка.
- Предложенные ответственные попали в письмо как факт → пометка «не подтверждено».
- Даты у задач без оценки → только оценка команды или выполненное.
- Коды WBS и ссылки на созвоны в названиях → убраны, `Q-NN` оставлены.
- Блок «Что нужно от вас» без просьбы PO → убран.

## Готово, когда

- [ ] .xlsx и письмо собраны командами из карты; руками не правились
- [ ] Числа письма совпадают с картой (вопросы открытые, без ответственного, цели, окна)
- [ ] Даты только с оценкой команды или у выполненного; полосы без оценки — «Оценка не подтверждена»
- [ ] Фактчек пройден, найденное исправлено в md и пакет пересобран
- [ ] Файлы в `reports/`, коммит, PO получил пути и одну строку счётчиков
