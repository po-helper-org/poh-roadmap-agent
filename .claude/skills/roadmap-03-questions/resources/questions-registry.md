# Реестр вопросов: шаблон и качество вопроса

Реестр — `.okr/roadmap/<slug>/questions.csv`, единственное место, где живут открытые вопросы и решения по стриму.
Формат и проверки `lint` — `okr-roadmap-viz/resources/format.md`; правила конституции — её статья V. Здесь то, что к
ним добавила практика: как сделать вопрос, на который придёт закрывающий ответ. Пустой шаблон —
`templates/questions.csv`; живой пример — `examples/school-migration/.okr/roadmap/courses/questions.csv`.

## Шапка и строка

UTF-8 с BOM, разделитель `;`, CRLF, ячейки с переносами — в кавычках. Пиши через `csv` в Python
(`delimiter=';'`, `lineterminator='\r\n'`, `encoding='utf-8-sig'`), а не правкой строки руками.

```
ID;Этап;Вопрос;Ответ;Ответственные;Влияет на;Критичный;Комментарий;Статус;История
Q-10;ЦС 2 · шаг 2.1;"Сохраняется ли у ученика оставшийся срок доступа к курсу после переноса, и по какой формуле он считается?";;"Бизнес-владелец 1, Бизнес-владелец 2";"s21 — 2.1 Бизнес утвердил правила переноса прогресса и оплаченного доступа
s21-1 — Решения бизнеса по сроку доступа и рассрочкам";;"Объединён с Q-12. Блокирует шаг 2.2: без правила нечего переносить. Ожидаемый ответ: да/нет и формула «срок в платформе Б = …» с примером. Источник: PO, 17.11.2026. Коммитмент: ответ до 01.12.2026 (PO, 17.11.2026).";Назначен;"12.11.2026 | Создан | Внесён в реестр (PO)
17.11.2026 | Назначен | Ответственные: Бизнес-владелец 1, Бизнес-владелец 2. Срок ответа: до 01.12.2026 (PO)
18.11.2026 | Назначен | Объединён с Q-12 (PO)"
```

## Колонки: кто заполняет и откуда

| Колонка | Что | Кто и откуда |
|---|---|---|
| ID | `Q-NN` по порядку, общий на все реестры цели | агент; снятый номер остаётся пропуском |
| Этап | «ЦС N · шаг N.k», диапазон шагов или «ЦС N в целом» | агент по «Влияет на» |
| Вопрос | один точечный вопрос | из источника; переформулировка — после «да» PO |
| Ответ | только полученный ответ, кто и когда ответил | человек или PO; пусто — открыт |
| Ответственные | кто даёт ответ | **только PO** |
| Влияет на | по строке на задачу: `<id> — <title из frontmatter>` | агент; первая строка — главная, в её группе вопрос показан на странице |
| Критичный | «да» или пусто | **только PO** или названный участник («ключевой блокатор») |
| Комментарий | по порядку: зависимость → что блокирует → **Ожидаемый ответ: …** → **Источник: …** → **Коммитмент: …** | агент собирает; срок — только от PO |
| Статус | Создан → Назначен → В работе → Ревью → Готово | по факту |
| История | `ДД.ММ.ГГГГ \| Статус \| заметка (кто решил)` по строке | каждое изменение |

## Правила качества вопроса

1. **Точечный.** Один вопрос — один ответ. Составной («деньги и юридическое оформление») разбиваешь.
2. **Ожидаемый ответ в конкретной форме:** таблица «X → Y»; матрица «пункт × процесс»; да/нет по каждому объекту;
   формула и порог («показатель, база сравнения, порог, периодичность, кто считает»); процесс по шагам с ролями;
   ссылка на документ, два имени подтвердивших и дата.
3. **Источник назван:** слова PO, пункт WBS с кодом, задача плана с номером, созвон и дата, пробел архива. Вопрос
   агента — после «да» PO, источник «PO, <дата>, <контекст>».
4. **Ответственный только от PO.** Кандидата по источникам пиши «кандидат — подтвердить PO» в «Комментарии».
5. **Срок ответа раньше старта блокируемого шага** — иначе вынести PO. «Если ответ не получен — сдвигаются сроки».
6. **«Влияет на» — к блокируемой задаче.** Вопрос шага — на шаг, вопрос подзадачи — на подзадачу и в её GAP. Вопрос
   нескольких целей — ко всем.
7. **Ценность.** Оставляешь, если ответ меняет решение, снимает блокировку или входит в приёмку. «Ради описания» —
   кандидат на снятие.
8. **В рамке цели.** Тему другого стрима переносишь туда строкой «Истории».
9. **Приёмка ответа описана.** У сводного вопроса прямо сказано, когда ответ принят: «документ, в котором ответы на
   вопросы шага, два имени подтвердивших и дата».
10. **Главный вопрос цели.** На каждую цель спроси: «какой ответ, если он изменится, переворачивает все остальные?»
    Обычно это полный конечный список объектов (курсов, витрин, клиентов). Пример: Q-09.
11. **Общий вопрос двух стримов** — в обоих реестрах под одним номером; в копии «Комментарий» начинается с «Общий
    вопрос с реестром «…» (тот же номер); ответ ведётся там». Ответ пишешь в основной, затем копируешь.

## Плохо → хорошо

| Плохо | Почему | Хорошо |
|---|---|---|
| «По какой схеме подключаем партнёров?» | «размазанный, непонятно, какой ответ ожидается» | «По какой схеме продаём через каждого партнёра: А, Б, В?» → таблица «партнёр → схема» |
| «Договорная обвязка?» | «очень абстрактный вопрос» | «Какие поля в договоре и на какие процессы влияет каждое: продажа, возвраты, расчёты, отчёты?» → матрица «пункт × процесс» |
| «Кто подписывает спецификацию?» | «непонятно, что значит „подписывает“» | «Документ спецификации готов, от каждой стороны названо одно имя подтвердившего» → ссылка, два имени, дата |
| «Деньги и юридическое оформление» | составной | Q-a: «Как идут деньги от покупателя до каждой стороны: кто, кому, в какой срок?» Q-b: «Список договоров между сторонами» → таблица «договор → стороны → предмет» |
| «Возвраты?» | одна тема — много ответов | «кто принимает заявку», «кто решает и по каким правилам», «кто и откуда возвращает деньги» → процесс по шагам |
| «Нужна ли полная обратная совместимость?» | с чем? PO признал необязательным | снять (в примере — Q-05) |
| «Условия сохраняются» (в DoD) | непроверяемо | «Как измеряем, что условия сохранились: показатель, база, порог, кто считает?» → формула и порог (Q-17) |
| — | главный вопрос пропущен | «Какие курсы входят в первую волну — полный конечный список?» (Q-09) |

## Реестр для руководства

Длинный реестр руководитель не читает («полная дичь, непонятная»). Ему нужны 3–5 критических решений:

```
1. <Что решить, простыми словами>
   Зачем: <какой шаг или цель без этого не стартует>
   Кто решает: <от PO> · Срок: <от PO>
   Если не решить: <что сдвинется — из графа карты, иначе «срок не подтвердить»>
   Вопросы реестра: Q-NN, Q-NN
```

Полный реестр — лист «Реестр вопросов» в .xlsx и страница карты. Топ-3 по цели выбирай из открытых вопросов без
новых смыслов: «Критичный: да» → блокирует самую раннюю работу → ключевой блокатор, названный PO.

## Подготовка к созвону

Выборка из реестра по одной команде и одной теме, с ожидаемым ответом у каждого вопроса (`bin/roadmap questions
<папка> [<id задачи>] --open`). После созвона: ответ, срок, статус — в «Ответ» и «Историю».
