# Этапы 3–4. Реестр вопросов: сбор и детализация

Ответ на «на чём держится срок» — список вопросов, без ответа на которые шаг не стартует, с ответственным и сроком.
Вопросы живут только в `questions.csv` своего стрима; на Ганте у задачи виден только их счётчик. Правила вопроса,
колонки и примеры «плохо → хорошо» — `resources/questions-registry.md` (прочитай перед первым вопросом).

## Этап 3. Сбор

1. Выписываешь из источников всё, что блокирует шаги: «ждём», «блокатор», «принять решение», «(?)», вопросы людей,
   пункты WBS «нужен ли вообще».
2. Показываешь кандидатов таблицей «вопрос → источник → какой шаг блокирует». Вопрос, выведенный тобой, помечаешь
   «предложение агента».
3. После «да» PO — строки в `questions.csv`: `Q-NN` по порядку (номера общие на все реестры цели), «Этап»,
   «Влияет на» к блокируемой задаче, «Комментарий» с «Источник: …», «Статус» Создан, «История».
4. Ссылаешься на `Q-NN` в GAP или DoD задачи. `bin/check-qlinks <папка>` — «Нарушений: 0».

## Этап 4. Детализация

1. Каждый вопрос доводишь до **точечного** с **ожидаемым ответом** в конкретной форме: таблица «X → Y», да/нет по
   каждому объекту, формула и порог, процесс по шагам с ролями, документ с двумя именами и датой. Не придумывается
   форма — вопрос ещё размазан.
2. Составной вопрос разбиваешь, вопрос вне рамки цели переносишь в свой стрим или снимаешь — строкой «Истории».
3. Ответственных, сроки ответа и критичность берёшь только у PO. Правило PO («все бизнес-вопросы — двум
   бизнес-владельцам, срок до 1-го») применяешь дальше и ссылаешься на него в «Коммитменте».
4. Срок ответа раньше старта блокируемого шага; позже — выносишь PO.
5. Назначения, сроки, слияния, ответы со созвона — строкой «Истории» `ДД.ММ.ГГГГ | Статус | заметка (кто решил)`.

## Спрашиваешь PO

- какие кандидаты вносим (этап 3);
- ответственных, сроки, критичность, кто принимает ответ (этап 4).

## Промпты PO

```
Выдели все вопросы, без ответов на которые не стартует шаг <N.k>. Только из источников, у каждого — откуда он.
Покажи таблицей «вопрос → источник → какой шаг блокирует». В реестр — после моего «да».
```

```
Пройдёмся по вопросам шага <N.k>: каждый — точечный, с ожидаемым ответом в конкретной форме.
Составные — разбей, вне рамки цели — убери. Покажи списком.
```

```
<Q-NN>: ответственный <роль/имя>, срок <дата>. Все бизнес-вопросы — <кто>, до <дата>. <Кто-то> не может быть ответственным.
```

```
Через 15 минут созвон с <командой>. Выведи все вопросы по <теме> к ним, с ожидаемым ответом.
```

## Ошибки, которые PO поправлял

- Агент сочинил вопросы, ответственных, срок и эскалацию → «Что за бред — откуда ты вообще эти вопросы взял?».
  Только из источника; поля пусты, пока их не дал PO.
- Ответственным поставлен системный аналитик → «не может быть ответственным ни за один из вопросов». Только PO назначает.
- «По какой схеме подключаем партнёров?» → «размазанный, нужна конкретика». Ожидаемый ответ — таблица.
- «Договорная обвязка?» → «абстрактный вопрос». Матрица «пункт договора × процесс».
- Вопрос другого стрима → «не относится к нашему стриму». Перенести.
- Ошибки в именах → написание сверяй с PO и меняй во всех материалах сразу.

## Готово, когда

- [ ] Каждый вопрос с «Источник: …» и «Ожидаемый ответ: …»; одна строка — один вопрос
- [ ] «Влияет на» — на блокируемую задачу, id существует; у каждого шага виден счётчик вопросов
- [ ] Ответственные, сроки, критичность — только от PO; где нет — пусто и пробел в отчёте
- [ ] Вопросы вне рамки перенесены или сняты строкой «Истории»; номера не переиспользованы
- [ ] `bin/check-qlinks` — 0 нарушений; `lint` — «Принято»; коммит
