# Этап 5. Полнота и ценность реестра

PO спрашивает прямо: «реестр полный и достаточный? Получив ответы на все — можно считать аналитику завершённой?»
Отвечаешь честно и по шагам. Правила вопроса — навык `roadmap-03-questions`, `resources/questions-registry.md`.

## Делаешь

1. По каждому шагу: «если получим ответы на все вопросы шага — можно его разработать и принять по DoD без новых
   вопросов?» Вердикт «достаточно / недостаточно» и причина.
2. Разводишь «аналитика завершена» и «цель достигнута»: цель достигается работой, а не ответами.
3. Отдельный проход по технике: канал интеграции, модель данных, обратная запись, оценки команд, согласование
   архитектуры, критерий технической готовности. В исходном проекте из 41 вопроса 39 были бизнесовыми. Технические
   ограничения из источников, которые стоят в тексте задач как допущения, — кандидаты в реестр.
4. Главный вопрос цели: «какой ответ, если он изменится, переворачивает все остальные?» Нет его в реестре — пробел.
5. Ценность: дубли — объединить; ответ не меняет решение, не снимает блок, не входит в приёмку — снять; широкий —
   разбить; чужой стрим — перенести. Это список предложений, файлы не меняешь до «да».
6. Итог PO: вердикт по шагам и два списка — «внесу механически» и «решить PO» (не больше 5, с рекомендацией).

## Рой агентов

Зови, когда PO просит «окончательное решение», «проверь роем», или перед тем как назвать реестр финальным.
Шаблон — `templates/workflows/completeness-workflow.js` (параметры через `args`: `base`, `map`, `units`, `decisions`,
`removed`, `scope`). Состав: аудитор на каждый шаг и на цель → два скептика на каждый пробел (линзы «источник» и
«покрытие») → пять сквозных проверок (дубли, ответственные и сроки, прослеживаемость, отвечаемость, карта ↔ реестр) →
критик полноты. Рой только читает. Пробел «подтверждён» — оба скептика не опровергли, «спорный» — один, «отклонён» —
ни один.

### Ручной режим (агент без инструмента Workflow: Codex и другие)

Те же роли — отдельными проходами по очереди. Тексты заданий бери из `completeness-workflow.js` (`CONTEXT`,
`auditPrompt`, линзы скептиков, `CROSS`, задание критика): подставь `map`, `units`, `decisions`, `removed`, `scope` сам.
Рабочие записи — в один файл вне карты (например `reports/Полнота_ЦС<N>_<ДД.ММ.ГГГГ>.md`): по разделу на проход.

1. **Список единиц.** По строке на каждый шаг ЦС и одну на ЦС целиком (`s11 … s14`, `ts1`); решения PO, которые
   нельзя оспаривать; снятые вопросы.
2. **Проход «аудитор»** — по единице за раз: заново прочитай файл единицы, её подзадачи, вопросы из «Влияет на» и
   источники. Запиши по полям `AUDIT_SCHEMA`: вердикт и причина, покрытые вопросы, пробелы (вопрос, ожидаемый ответ,
   зачем, цитата «файл: фрагмент», серьёзность), вопросы без ценности (рекомендация), неясные (как переписать).
3. **Проход «скептик: источник»** — по каждому пробелу: перечитай только карточку пробела и `sources/`; цель —
   опровергнуть. Цитаты нет в файле или она не про это — `real: нет`.
4. **Проход «скептик: покрытие»** — по каждому пробелу: перечитай реестр и `backlog/`; закрыт ли пробел вопросом,
   пунктом DoD, другим шагом или решением PO (`covered_by`: Q-NN или файл).
5. **Статус пробела** — по двум голосам: оба `real: да` — «подтверждён», один — «спорный», ни одного — «отклонён»;
   проход не сделан — «не проверено». Правило то же, что в рое: без «подтверждён по ощущению».
6. **Сквозные проверки** — пять проходов `CROSS` по всему реестру `scope` (можно одним проходом с пятью разделами).
7. **Критик полноты** — последний проход по сводке: слепые зоны, противоречия между аудитами, можно ли честно сказать
   «аналитика завершена» и при каких допущениях.

Чтобы проходы были независимыми: каждый начинай с чтения файлов, а не с выводов прошлого прохода; скептику давай
только карточку пробела, не рассуждение аудитора. Умеешь запускать субагентов — по субагенту на проход, тексты те же.
Файлы карты в проходах не меняются; итог PO — тот же, что после роя (вердикты, «внесу механически», «решить PO»).

## Промпты PO

```
Реестр вопросов по ЦС <N> полный и достаточный? Получив ответы на все — можем считать аналитику завершённой?
Ответь по каждому шагу. Отдельно: технические вопросы все разобраны? Какой главный вопрос цели?
```

```
Пройдись по вопросам ЦС <N>: каждый ли раскрыт и имеет ценность? Дубли — объединить, без ценности — снять,
широкие — разбить. Список предложений, файлы пока не меняй.
```

```
Используй рой агентов, провалидируй финальный список вопросов по ЦС <N>. Хочу окончательное решение:
что внести механически и что решить мне.
```

## Ошибки, которые PO поправлял

- Соблазн сказать «да, полный» → полнота всегда «относительно источников»; неизвестные неизвестные реестр не покрывает.
- Главный вопрос цели первым назвал PO, а не агент → задавай вопрос «что переворачивает всё» на каждой цели.
- У части шагов вопросов не было вовсе → вердикт по каждому шагу, а не по цели целиком.

## Готово, когда

- [ ] Вердикт «достаточно / недостаточно» по каждому шагу и цели
- [ ] Разведены «аналитика завершена» и «цель достигнута»
- [ ] Отдельный проход по технике; назван главный вопрос цели
- [ ] Дубли, вопросы без ценности и широкие — предложены PO; после «да» внесены, слияния и снятия — в «Истории»
- [ ] Если звали рой (или прошли ручной режим): подтверждённые / спорные / отклонённые пробелы; «внесу механически» отделено от «решить PO»
- [ ] `check-qlinks` — 0, `lint` — «Принято», коммит
