# Этап 2. Путь объекта — шаги ЦС

Список работ по компонентам («справочники, база, админка») не отвечает на «что нужно, чтобы всё заработало». Путь
одного объекта отвечает. Правила шага — `constitution.md`, принцип 4 и статья II.2; шаблон — `templates/backlog/step.md`.

## Делаешь

1. Выбираешь объект, который проходит через системы (курс, заказ, договор, мероприятие), и пишешь его путь от
   источника к результату. Шаг — `<N>.<k> <объект> <состояние> в <системе>` или `<N>.<k> <роль> <может> в <системе>`.
2. Бизнес-цель раскладываешь так, чтобы бизнес читал шаги сверху вниз: каждый шаг — единица с измеримым результатом
   «да/нет к дате».
3. Показываешь в чате, в карту не вносишь: таблица «№ → результат да/нет → окно плана → откуда» и три глубины —
   ЦС (руководителю: будет ли и когда), шаги (всем: что должно заработать), работы (командам: что сделать).
4. После «путь подтверждаю» — файлы `backlog/s<N><k>`, ЦС становится полосой по окнам шагов (`type: task`).

## Не бывают шагом

| Что | Куда |
|---|---|
| работа («сделать API», «поднять базу») | подзадача (этап 6) |
| решение («утвердить схему») | вопрос в реестре (этап 3); бизнес-шаг «Бизнес утвердил…» — только по слову PO |
| критерий приёмки («заказчик видит…») | пункт DoD ЦС |
| свойство результата («изменения доходят») | пункт DoD |
| инструмент («отчёты уходят в учётную систему») | никуда — «инструмент не входит в результат» |
| условие старта («билеты и чеки по требованиям») | пункт DoD соседнего шага |
| сомнительный объём («особые условия») | вопрос «нужно ли вообще»; шаг «…, если нужны» |

## Спрашиваешь PO

- «Путь такой — подтверждаете?»;
- какие шаги лишние, какие слить;
- что из списка — условие старта или пункт DoD, а не шаг.

## Промпты PO

```
Какой объём работ нужен, чтобы прийти к ЦС <N> «<формулировка>»? Разложи по пути одного <объекта> через системы,
а не по компонентам. Покажи на трёх уровнях: руководителю, всем участникам, командам. В карту пока не вноси.
```

```
Декомпозируй ЦС <N> так, чтобы сверху вниз легко читался план работ для бизнеса: всё, что с цифрой, — бизнес-ценная
единица с измеримым результатом. Только из источников.
```

```
Окей, занеси в Roadmap. Правки: <«X — инструмент, убери»; «Y — условие старта, а не этап»>.
```

## Ошибки, которые PO поправлял

- Шаг-приёмка «Заказчик видит результат» → «удалить», это DoD цели.
- Шаг «Изменения у источника доходят до системы» → «это просто один из DoD».
- Шаг «Решения до старта» с блокаторами-вехами → вопросы в реестр, «блокаторы убрать из Ганта».
- PO написал «утвердили» → агент не поставил «Выполнено», а спросил кто, когда и где утвердил. Так и надо.

## Готово, когда

- [ ] Назван объект, путь которого раскладываем
- [ ] Каждый шаг — измеримое состояние, не работа, не решение, не приёмка
- [ ] PO сказал «путь подтверждаю» до наполнения
- [ ] ЦС стал полосой по окнам шагов; у каждой даты — «Основание даты»
- [ ] `lint` — «Принято», коммит, страница у PO
