# Этап 11. Ежедневная актуализация и дейлик

Карта живёт после планирования: каждый день (или по расписанию) агент переносит в неё то, что сказали PO и команда,
и выпускает **один отчёт** — `reports/daily/ГГГГ-ММ-ДД.md`, привязанный к целевым состояниям Roadmap. Отчёт строит
команда `bin/roadmap daily` из файлов карты, а не агент из памяти. Переносимый промпт для запланированной сессии
любого агента — `templates/daily-brief.md`; формат отчёта и правила расчёта — `okr-roadmap-viz/resources/format.md`,
раздел «Дейлик».

## Когда

- По расписанию: scheduled task Claude Code, cron Codex — с промптом из `templates/daily-brief.md`.
- По слову PO: «дейлик», «что изменилось за день», «статус по целям на сегодня».
- После созвона, если PO просит сразу обновить карту и отчёт.

Нужна карта, прошедшая этапы 0–2 (ЦС и шаги есть, `lint` — «Принято»). Без журнала отчёт тоже формируется: прогресс
— из md и статусов.

## Алгоритм одного запуска

1. **Обнови репозиторий** — `git pull --ff-only`. Конфликт или незакоммиченные правки — не правь, сообщи PO, стоп.
2. **Собери обновления только из источников:** сообщения PO в сессии, новые файлы в `sources/`, подключённые системы
   задач — только если они реально доступны и PO назвал, что оттуда брать. Нет данных — не придумывай прогресс:
   журнал не трогаешь, отчёт всё равно формируется («изменений за период нет» и риски). Реплики PO — дословно с датой
   в `sources/po-messages.md`.
3. **Запиши изменения** по правилам этапа 8 (`roadmap-08-comments`): строки в конец `journal.csv` папки стрима
   (UTF-8 с BOM, `;`, CRLF), прогресс задачи — ещё и в её frontmatter `progress`/`status`; ответы, сроки и новые
   вопросы — в `questions.csv`. Таблица «PO сказал → куда» — в `templates/daily-brief.md`.
4. **Проверь и собери:** `bin/roadmap lint <папка цели>` — «Принято», `bin/check-qlinks <папка цели>` — «Нарушений: 0»,
   `bin/roadmap build <папка цели> -o roadmap.html`.
5. **Отчёт:** `bin/roadmap daily <папка цели> --date <сегодня>` — период по умолчанию с прошлого отчёта в
   `reports/daily/` (нет — 7 дней), `--since` — явное начало, `-o` — другой файл.
6. **Коммит** одним сообщением: `Дейлик ГГГГ-ММ-ДД: <строка «Итог» отчёта коротко>`.
7. **Ответ PO** — 5–7 строк (формат ниже).
8. **Вопросы PO о статусе** в этой же сессии — только по карте, журналу и последнему отчёту: `bin/roadmap tree`,
   `bin/roadmap questions <папка> [<id>] [--open]`, `reports/daily/<последний>.md`. Ссылайся на id задач и `Q-NN`.
   Чего нет в данных — «в данных нет».

## Строки журнала

```
Дата;Объект;Тип;Прогресс;Статус;Текст;Автор
2026-11-20;w1-1-1;прогресс;70;В работе;Поля курса выгружаются все, кроме тегов;Техлид контура А
2026-11-21;w1-1-2;прогресс;0;Заблокировано;Приём каталога ждёт ответа на Q-01 по полям курса;
2026-11-21T18:00;ts3;комментарий;;;Вопрос PO: у ЦС 3 нет ни шагов, ни дат — когда разбираем партнёрские витрины?;агент
```

- Дата — день, когда пришло обновление (обычно сегодня). Прошлых дат не выдумывай: период отчёта считается по ним.
- Объект — id задачи из `backlog/` папки стрима (`s11`, не `1:s11`) или `Q-NN` её реестра.
- Вопрос агента к PO — комментарий с Автором «агент» и Текстом «Вопрос PO: …». Он стоит в «Вопросах к PO на завтра»,
  пока о том же объекте не появится запись не от агента (ответ PO, записанный тобой).

## Правила

- **Один запуск — один отчёт.** Отчёт руками не правишь; нужна другая подача — правишь данные и собираешь заново.
  Прошлые отчёты не трогаешь: команда откажется перезаписать отчёт, после которого уже есть более поздний.
- **Не меняешь без слова PO:** даты, ответственных, исполнителей, критичность, «Выполнено» (только когда известно, кто,
  когда и где принял).
- **Сессия без человека:** ничего не решаешь за PO. Неясное — строкой «Вопрос PO: …» в журнал и в ответ; правки,
  требующие решения, не делаешь.
- **Даты в дейлике — как на карте**, у задачи без своей оценки команды — пометка «(оценки нет)». Правило пакета
  руководству «даты только по оценке команды» (этап 9) в дейлике не скрывает даты: отчёт для PO и команды, ему нужно
  видеть план; пометка показывает, где оценки нет.
- **Срок ответа на вопрос** — «Срок ответа: до ДД.ММ.ГГГГ» в «Комментарии» или «Истории» (последнее «до …» — срок,
  как в .xlsx). Без такой записи вопрос не попадает в просроченные.

## Ответ PO

```
Дейлик ГГГГ-ММ-ДД: <строка «Итог» отчёта>.
Цели: <трек · ЦС N было → стало; без изменений — «без изменений»>.
Вопросы: закрыто <Q-NN>, новых <Q-NN>.
Риски: <просрочено / заблокировано / просрочены ответы — id>.
Отчёт: reports/daily/ГГГГ-ММ-ДД.md, коммит <sha>.
Вопросы к вам: 1. <из раздела «Вопросы к PO на завтра»> 2. …
```

## Ошибки, которых избегаем (из пробного запуска без формата)

- Агент сам придумал формат и посчитал процент цели «средним по шагам» на глаз → правило расчёта и формат в команде
  `daily`, одинаковые для всех агентов.
- ЦС показывала 0%, когда её шаг был на 70% → прогресс без своей записи — расчёт по подзадачам.
- Срок ответа искали в произвольном тексте → только «до ДД.ММ.ГГГГ», тем же разбором, что в .xlsx.
- Отчёт пересказывал весь реестр → в отчёте только закрытое и новое за период, открытые критичные и без ответственного.

- [ ] `lint` — «Принято», `check-qlinks` — 0, страница пересобрана

- [ ] Коммит «Дейлик ГГГГ-ММ-ДД: …», PO получил 5–7 строк, путь к отчёту и вопросы к нему
